# 第10套挖空版与答案版对照

| 挖空文件 | 题目编号 | 答案实现 | 业务要点 |
|---|---|---|---|
| `PensionAccount.sol` | ① | `generatePensionAccount` | 依次调用姓名、年龄、雇主、开始日期、工资、缴费基数 stub 并存储 |
| `PensionInsurance.sol` | ② | `addEmployee` | 仅管理员添加不存在的职工账户，余额为0且非赞助商 |
| `PensionInsurance.sol` | ② | `addEmployer` | 仅管理员添加不存在的雇主账户，余额为0且为赞助商 |
| `PensionInsurance.sol` | ② | `makePayment`/`removeEmployee` | 按3200至24000基数计算8%和19%，检查30天，安全减员 |
| `PensionTransfer.sol` | ③ | `applyTransfer` | 按顺序记录申请人、原城市、目标城市、停缴、批准状态 |
| `PensionTransfer.sol` | ③ | `authorizeTransfer`/`receiveAccount` | 社保局核验停缴、授权和接收个人基金、统筹基金、养老保险账户 |

## 与官方答案的关键修正

- 官方费用合约通过余额是否大于0判断账户存在，导致新账户无法按题意建立；答案版增加 `exists` 和 `active`。
- 官方 `removeEmployee` 同时要求余额大于0和余额等于0，条件永远不能满足；答案版要求无余额后将 `active` 设为false。
- 官方转移逻辑把 `applications[i]` 复制到 memory 后修改，状态不会写回链上；答案版按 application ID 使用 storage。
- 官方 `authorizeTransfer` 对 `isStopped` 的分支和批准语义相反；答案版明确停缴为 `true` 时允许转移，并记录社保局授权。
- 公安、劳动、社保外部接口在题目中未提供 ABI；答案版使用确定性的内部纯函数 stub，README 中明确了替换边界。
